# Serpantinum evaluation

## Decision

Serpantinum is not adopted as the active desktop base. It is useful as a visual reference, but its current repository is a personal NixOS configuration rather than a reusable flake module suitable for this project.

## Compatibility findings

| Area | Serpantinum | nix-conf requirement | Decision |
|---|---|---|---|
| Flake boundary | No self-contained flake module; imports Home Manager through a channel path | Reproducible flake inputs and explicit outputs | Reject direct import |
| Hardware | Contains host-specific AMD/NVIDIA assumptions and kernel parameters | Separate Latitude ext4/Intel and myMachine Btrfs/graphics policy | Reject direct import |
| Paths | Assumes `/etc/nixos/config` and personal paths | Checkout is `~/.config/nixos`; no `/etc/nixos` ownership | Reject direct import |
| Hyprland format | Uses hyprlang `.conf` fragments and `source` directives | Current Hyprland uses Lua and the end-4 source has a native Lua entrypoint | Full rewrite required |
| Runtime state | Uses imperative `rsync --update` activation into user config | Static assets may be immutable; runtime state must remain user-owned | Do not copy the activation model |
| Repository status | README warns that the NixOS installation path still needs adaptation | Must pass the Nix evaluation and activation gates | Do not use as base |

The direct migration would reintroduce the failure already observed: a legacy `.conf` tree would be mixed with a Lua configuration generated by Home Manager. It would also make ownership unclear between Nix, activation scripts, and user edits.

## Safe reuse

Only isolated visual ideas may be ported later. Each asset would need a license check, an independent Nix expression, and a compatibility test against the pinned Hyprland, QuickShell, Matugen, and Home Manager versions. No Serpantinum code is evaluated by the active flake.
